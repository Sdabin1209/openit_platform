# 0005 환경 검증: 계약 Env 스키마를 이미지 안에서 해석한다 (envcheck)

- 상태: 채택
- 맥락: 계약 3.4.10 이 platform 이미지마다 Env 스키마(이름·형식·기본값·필수)를 정한다. 이미지가 그것을 지키는지 기동 때 확인하지 않으면 이름 오타·형식 위반이 조용히 기본값으로 가려진다.
- 결정: `common/envcheck`(Go, 표준 라이브러리만)가 스키마 파일(JSON Schema 의 `properties`·`$defs`·`required`·`propertyNames`·`allOf if/then const` 부분집합)을 읽어 환경을 검증하고 기본값을 채운다. 모든 이미지가 빌드 때 계약 스키마를 `/etc/openit/schemas/` 에 넣고 진입점에서 실행한다. 위반이면 종료 64.
- 왜: 이름·패턴·기본값의 정본은 계약이다. 이미지에 같은 값을 손으로 쓰면 계약이 바뀔 때 어긋난다. 스키마를 해석하면 한 곳이다. 부분집합만 구현한 이유는 현재 Env 스키마가 쓰는 키가 그것뿐이어서다 — 스키마가 새 키워드를 쓰면 시험(변이)이 잡도록 이름 위반·필수·조건부 필수를 이미지별로 시험한다. Go 인 이유는 ADR 0004.
- 검토한 대안: python-jsonschema(전체 키워드 지원) — 셸·파이썬 없는 이미지가 있다. 이미지마다 손으로 쓴 검증 — 계약과 어긋난다.
- 결과: 계약에 없는 `INGRESS_`·`GATEWAY_` 같은 이름(예: 옛 `INGRESS_BUILTIN`, `GATEWAY_HOST_NAMES`)은 거절된다 — deploy 가 옛 이름을 주면 바로 알게 된다. 감수하는 것: 스키마가 새 키워드를 쓰면 envcheck 를 고쳐야 한다.
- 되돌리는 조건: 모든 이미지에 검증 가능한 런타임이 생길 때.
