# 0016. 기기 허용 목록과 사용자 ID: ADR 0013 의 Nygard 항목 보완

## 상태
채택. [ADR 0013](0013-계약-4-기기-허용목록과-사용자-ID.md)(2026-11-07)에 없던 맥락·왜·검토한 대안·되돌리는 조건을 채운다. 결정 내용은 0013 과 같고 바뀌지 않았다. 근거는 계약 CHANGELOG 4.0.0·4.0.5 와 구현 커밋 95ea138 이며 그 밖에서 지어내지 않았다.

## 맥락
계약 4.0.0(2026-11-07, MAJOR)이 "기기 인증은 mTLS 하나(D136)"로 정했다. DeviceAllowlist 가 신설되고 DeviceConfig.device_token·KioskStartFragment.device·INGRESS_DEVICE_TOKENS_DIR 등 기기 토큰 관련 항목이 제거됐으며, Exposure auth `device-token` 은 `device` 로 바뀌었다. 인증서 없음·목록 밖은 403 이다. 이전 platform 은 `ingress/gen-devices.py` 로 기기 토큰 Caddy 조각을 만들었다. 같은 4.0.0 에서 HumanUserId 정본과 IdentityUsersConfig 도 정해졌다.

## 결정
0013 본문과 같다: 검증된 인증서의 CN·serial 을 비공개 Unix 소켓 확인기(`ingress/device-auth.py`)에 전달하고, 확인기가 DeviceAllowlist 를 매 요청 다시 읽어 계약 검증기로 확인한다. 파일 오류·중복 기기는 503(fail-closed). 사용자 ID·백업 결과 검증은 0013 본문.

## 왜
- 계약 4.0.0 이 기기 인증을 mTLS 하나로 확정했다(D136). TLS 가 인증서를 검증하고 확인기는 허용 목록만 본다.
- 목록을 요청마다 읽으면 같은 TLS 연결에서도 회전·폐기가 즉시 적용된다(커밋 95ea138 의 시험: mTLS 회전/폐기·장애 회복). 부모 디렉터리를 마운트하는 이유는 파일 교체(rename)가 단일 파일 바인드 마운트에서는 보이지 않기 때문이다. 이 이유는 구현 의도로 추정한 것이며, 별도 측정 기록은 찾지 못했다.
- 확인 장애를 503 으로 해 상류 연결·시간 초과와 구분하고, 허용 판단을 못 하는 상태에서 열지 않는다.

## 검토한 대안과 버리는 이유
- 기기 토큰 유지(이전 방식): 계약 4.0.0 이 제거했으므로 불가.
- 허용 목록을 시작 때만 읽기: 회전·폐기가 재시작까지 안 보인다. 요청마다 읽는 비용은 측정하지 않았다.
- 그 밖에 Caddy 내부 인증 방식들을 비교한 기록은 리포·계약 CHANGELOG·git log 어디에서도 찾지 못했다.

## 결과 / 되돌리는 조건
얻는 것: 즉시 폐기, 계약과 일치. 감수하는 것: 요청마다 파일 읽기·검증 비용(측정 안 함), 목록이 깨지면 기기 경로 전체가 503. 계약이 기기 인증 방식을 바꾸거나(새 MAJOR) 요청당 읽기 비용이 측정으로 문제가 되면 새 ADR.
